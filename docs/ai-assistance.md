# AI 回覆與轉真人

預設關閉。設定 `OPENCODE_GO_API_KEY` 且 `AI_AUTO_REPLY_ENABLED=true` 後，新客服單先進入 AI 模式；開單及客戶後續公開回覆會在同一筆資料庫交易排入 AI 工作。主旨以使用者訊息傳送，最近公開文字會送到 OpenCode Go 的 DeepSeek V4.1 Flash；客服單類別用於選擇部門指令。附件、IP、登入紀錄和內部備註不會送出。建單頁會告知使用者文字傳送與轉真人選項。

管理員可在 `/admin/ai` 編輯一般、帳務、技術支援三個部門的完整系統指令。客服單依開單時的問題類別選用對應指令；空白欄位不傳送系統指令。服務端不再加入固定角色或回覆規則。儲存後，尚未處理的 AI 工作會讀取最新指令。模型仍由程式設定，不能從網頁改動。

部門欄位是 API 的唯一系統指令來源，不套用其他部門的預設指令。主旨及對話以原文傳送，不加入「客服單主旨：」或其他固定前綴；非服務時間提示與自動訊息也不當作 AI 指令傳送。

工作由同一個 Go 服務的背景 worker 非同步處理，不阻塞建單。worker 使用 PostgreSQL 工作表、唯一訊息 ID、租約與重試。模型回覆前會在交易內重新檢查客服單模式、狀態及最新客戶訊息；若已轉真人、已結案或有更新訊息，丟棄舊回覆。三次失敗或工作超過 24 小時時，客服單改由真人處理。AI 訊息會標明「AI 回覆」，使用者可隨時按「轉真人客服」。

AI 新客服單及使用者後續回覆進入「處理中」，顯示「AI 處理中」；AI 完成回覆後改為「待客戶回覆」，畫面顯示「AI 已回覆 · 待您確認」。使用者尚未轉真人時，後續公開回覆會再次交給 AI，包含最近的公開對話內容。等待 AI 時只更新對話及狀態，不會清除尚未送出的回覆；完成後停止輪詢。

AI 回覆下方提供「已解決」及有顏色的「轉真人客服」按鈕。只有客服單擁有者可以確認已解決，且須符合最新版本，避免舊按鈕覆蓋新問題；確認後記錄狀態變更，並套用管理員設定的自動結案天數與站內通知。未轉真人的已解決客服單再次回覆，仍交給 AI，並取消原本的結案倒數。轉真人或真人客服公開回覆後，AI 不再介入。

在 VPS 的互動式終端執行 `sudo bash scripts/set-opencode-go-key.sh`，輸入金鑰後再執行 `docker compose up -d --no-deps app`。腳本只寫入權限 600 的 `.env`，不會顯示金鑰或放進命令歷史。若已自行加入金鑰，也須設定 `AI_AUTO_REPLY_ENABLED=true` 並重建 app 容器。需要停用時，將此設定改為 `false` 並重建 app 容器；既有 AI 客服單應由客服手動接管。

OpenCode Go [官方文件](https://opencode.ai/docs/go/)提供上述模型與 API 端點，也說明它主要面向程式開發代理。客服用途應先向服務供應商確認適用範圍。自動化測試使用本機模擬服務，不會以正式金鑰呼叫模型。
